# TSP — سامانه مدیریت تست، مطالعه و آمادگی آزمون

**TSP** = Test + Study + Prep — سامانه‌ای برای دانش‌آموز رشتهٔ **ریاضی-فیزیک** که تست‌های کتاب‌های
کمک‌آموزشی را سازمان می‌دهد، تاریخچهٔ حل را نگه می‌دارد و درصد و آمادگی را از روی همان تاریخچه
محاسبه می‌کند.

> **نسخهٔ فعلی: ۰.۲ (مرحلهٔ ۲ از ۶)** — زیرساخت (مدل دادهٔ Prisma، قالب فارسی/راست‌به‌چپ،
> ابزارهای پایه) و **سامانهٔ احراز هویت** (ثبت‌نام، ورود، محافظت از مسیرها، خروج) آماده است.
> صفحه‌های ماژول‌ها در مراحل بعدی کامل می‌شوند (نقشهٔ راه در پایان همین فایل).
>
> **اجرا روی ویندوز:** همهٔ دستورها نسبت به مسیرها و پوستهٔ ویندوز مقاوم شده‌اند؛ اگر
> تازه شروع می‌کنید، بخش «راه‌اندازی سریع» را ببینید. برنامه حتی بدون فایل `.env` هم
> بالا می‌آید و به‌جای صفحهٔ سفید، راهنمای فارسی نشان می‌دهد.

## ۲) راه‌اندازی سریع

نیازمندی: **Node.js 20.9 یا بالاتر** (پیشنهاد: ۲۲) و npm.

فقط این سه دستور را اجرا کنید — به همین ترتیب:

```bash
npm install
npm run db:setup
npm run dev:open
```

پس از چند ثانیه، مرورگر خودکار روی `http://localhost:3000` باز می‌شود. نخستین بار از
صفحهٔ **«ثبت‌نام»** حساب خودتان را بسازید (اولین حساب، صاحب داده‌های محلی شماست).

| دستور | کار |
|--------|------|
| `npm install` | نصب بسته‌ها + ساخت خودکار فایل `.env` + تولید کلاینت Prisma |
| `npm run db:setup` | ساخت فایل پایگاه دادهٔ محلی، ساخت ۱۷ جدول و تولید کلاینت Prisma |
| `npm run dev:open` | اجرای برنامه + باز کردن خودکار مرورگر |

> **بدون نگرانی:** اگر `.env` نباشد، در `npm install` و در `npm run dev:open` خودکار ساخته
> می‌شود (با `AUTH_SECRET` تصادفی). اگر پایگاه داده نباشد هم دستور `dev:open` خودش آن را
> می‌سازد. حتی اگر هیچ‌کدام ساخته نشده باشد، برنامه **بالا می‌آید** و در صفحهٔ ورود یک کادر
> راهنمای فارسی می‌گوید چه دستوری باید اجرا شود (هیچ‌وقت صفحهٔ سفید یا خطای ۵۰۰ نمی‌بینید).

بررسی سلامت برنامه و اتصال پایگاه داده: `http://localhost:3000/api/health`

### فایل محیطی

فایل `.env` خودکار ساخته می‌شود؛ ولی اگر خواستید دستی بسازید، آن را از `.env.example`
کپی کنید (یا `npm run init:env`) و مطمئن شوید این دو خط را دارد:

```env
DATABASE_URL="file:./prisma/dev.db"
AUTH_SECRET="یک-رشتهٔ-تصادفی-بلند"
```

ساخت `AUTH_SECRET`:

```bash
npm run init:env -- --force
# یا
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

> **نکتهٔ مهم ویندوز:** در فایل `.env` دور علامت `=` فاصله نگذارید (`AUTH_SECRET=x` درست است،
> `AUTH_SECRET = x` نادرست). برنامه خط‌های نادرست را نادیده می‌گیرد و دلیلش را به فارسی
> در کنسول و صفحهٔ ورود توضیح می‌دهد.

اگر `AUTH_SECRET` تنظیم نشده باشد:
- **حالت توسعه:** یک کلید موقت ثابت استفاده می‌شود تا برنامه بالا بیاید (با هشدار فارسی)؛
  با هر بار اجرا باید دوباره وارد شوید.
- **حالت تولید:** ورود غیرفعال می‌شود و به‌جای خطای مبهم، پیام فارسی و راه‌حل نمایش داده می‌شود.

## ۳) فرمان‌های مفید

| فرمان | کار |
|--------|------|
| `npm run dev` | اجرای برنامه در حالت توسعه (بدون باز کردن مرورگر) |
| `npm run dev:open` | اجرای برنامه + باز شدن خودکار مرورگر |
| `npm run build` / `npm start` | ساخت و اجرای نسخهٔ نهایی |
| `npm run lint` | بررسی کد با ESLint |
| `npm run typecheck` | بررسی نوع‌ها با TypeScript |
| `npm run test:unit` | آزمون‌های واحد (تاریخ شمسی، اعتبارسنجی، محیط، اسکریپت‌ها) |
| `npm run db:setup` | ساخت/هم‌گام‌سازی پایگاه داده (فایل `.env` را هم می‌سازد) |
| `npm run db:check` | نمایش وضعیت پایگاه داده بدون تغییر چیزی |
| `npm run db:reset` | پاک‌کردن و ساخت دوبارهٔ پایگاه داده (بی‌بازگشت) |
| `npm run init:env` | ساخت/اصلاح فایل `.env` و کلید `AUTH_SECRET` |
| `npm run doctor` | **عیب‌یابی گام‌به‌گام** با گزارش فارسی و راه‌حل هر مشکل |

> **نکته:** پیش از اجرای `npm run build` سرور توسعه را ببندید؛ هر دو از پوشهٔ `‎.next‎`
> استفاده می‌کنند و ساخت نسخهٔ نهایی، فایل‌های سرور در حال اجرا را بازنویسی می‌کند.


### ساخت مهاجرت تازه

پس از هر تغییر در `prisma/schema.prisma`:

```bash
npx prisma migrate dev --name توضیح_تغییر   # ساخت فایل مهاجرت (نیازمند اینترنت معمولی)
npm run db:deploy                           # اعمال مهاجرت‌ها روی پایگاه داده
```

> **نکتهٔ فنی:** پروژه روی «موتور طرح‌وارهٔ جاوااسکریپتی» Prisma (بدون باینری بومی) تنظیم شده تا
> روی ویندوز و هر سیستم‌عامل دیگری **بدون دانلود فایل‌های سنگین** اجرا شود. این موتور هنوز
> آزمایشی است و برای `migrate dev` نمی‌تواند پایگاه دادهٔ سایه بسازد؛ به همین دلیل:
> • در کار روزمره از `npm run db:setup` (که از `db push` استفاده می‌کند) یا `npm run db:deploy`
>   استفاده کنید؛
> • ساخت *فایل* مهاجرت تازه را روی سیستمی با اینترنت معمولی انجام دهید (موتور کلاسیک خودکار
>   دانلود می‌شود).

## ۵) مدل داده

مدل دادهٔ `prisma/schema.prisma` بر پایهٔ سند `TSP_v0.2_docs/03_Data_Model_v0.2.md` نوشته شده و
۱۷ مدل دارد:

| گروه | مدل‌ها |
|------|---------|
| کاربر | `User` |
| کتاب و ساختار | `Book`, `BookNode` |
| مبحث | `Topic`, `QuestionTopic` |
| تست و تاریخچه | `Question`, `QuestionAttempt`, `PreviousSolvedEntry` |
| تدریس | `TeachingRecord`, `TeachingGoal` |
| آزمون | `Exam`, `ExamTopic`, `ExamQuestion`, `ExamAttempt`, `ExamAnswer` |
| برنامهٔ آینده | `FutureExamPlan` |
| مرور | `ReviewItem` |

### قواعدی که در مدل داده رعایت شده است

1. **`displayNumber` یکتا نیست** — شمارهٔ نمایشی در هر فصل از ۱ شروع می‌شود؛ شناسهٔ واقعی همان
   `Question.id` است.
2. **`BookNode` جدا از `Topic`** — اولی محل تست در کتاب است و دومی مفهوم آموزشی.
3. **تاریخچه فقط افزودنی** — هر بار حل، یک `QuestionAttempt` تازه می‌سازد و رکورد قبلی هرگز
   بازنویسی نمی‌شود.
4. **`PreviousSolvedEntry` با `QuestionAttempt` یکی نیست** — برای تست‌هایی که پیش از استفاده از
   برنامه حل شده‌اند.
5. **سختی ناشر، `isHard` و `isImportant` سه فیلد جدا هستند.**
6. **آمار از رکوردهای خام محاسبه می‌شود** — هیچ فیلد خلاصه‌ای جای تاریخچه را نمی‌گیرد.
7. **`onDelete` مناسب هر رابطه** — حذف کتاب، ساختار و تست‌هایش را پاک می‌کند (`Cascade`)؛ حذف
   یک تست بانک، سؤال آزمون را نگه می‌دارد و فقط پیوندش را خالی می‌کند (`SetNull`).

> **چرا enum نداریم؟** SQLite در Prisma از `enum` پشتیبانی نمی‌کند؛ مقادیر مجاز به‌صورت `String`
> ذخیره می‌شوند و مرجع تایپ‌شدهٔ آن‌ها در `lib/constants.ts` است.

## ۶) احراز هویت

ورود و ثبت‌نام با **NextAuth.js 5 (Auth.js)** و فراهم‌کنندهٔ **Credentials** انجام می‌شود:

- **ثبت‌نام**: `POST /api/auth/register` ورودی را با Zod بررسی می‌کند، گذرواژه را با bcrypt
  (۱۰ دور) هش می‌کند و کاربر را می‌سازد. ایمیل تکراری کد ۴۰۹ می‌گیرد.
- **ورود**: فرم ورود با `signIn("credentials")` وارد می‌شود؛ در `lib/auth.ts` ابتدا ایمیل پیدا
  و سپس گذرواژه با هش مقایسه می‌شود. نشست به‌صورت **JWT** در کوکی `HttpOnly` نگه داشته می‌شود
  (۳۰ روز).
- **محافظت از مسیرها**: `middleware.ts` همهٔ مسیرها را می‌گیرد و مسیرهای خصوصی را به
  `/login?callbackUrl=...` می‌فرستد؛ کاربر واردشده هم از صفحه‌های ورود/ثبت‌نام به داشبورد
  برمی‌گردد. میدل‌ور در Edge اجرا می‌شود، پس فقط `lib/auth.config.ts` سبک را می‌خواند و
  Prisma/bcrypt در آن بار نمی‌شود.
- **خروج**: دکمهٔ خروج در نوار بالایی کوکی نشست را پاک می‌کند.

نکته‌های امنیتی رعایت‌شده: گذرواژهٔ هش‌شده هرگز از API بیرون نمی‌رود، پیام خطای ورود همیشه
عمومی است («ایمیل یا گذرواژه نادرست است») تا معلوم نشود کدام ایمیل ثبت شده است، و مقصد
بازگشت پس از ورود (`callbackUrl`) با `safeCallbackUrl` پاک‌سازی می‌شود تا دامنهٔ بیرونی
جای مسیر داخلی ننشیند.

## ۷) تاریخ شمسی

- همهٔ تاریخ‌ها به شکل **میلادی/ISO** ذخیره می‌شوند و فقط برای نمایش به شمسی تبدیل می‌شوند.
- توابع آماده در `lib/date.ts`:

```ts
formatJalali(new Date("2025-09-22"));                  // ۱۴۰۴/۰۶/۳۱
formatJalali(new Date("2025-09-22"), { long: true });  // ۳۱ شهریور ۱۴۰۴
parseJalali("1404/06/31 14:30");                       // Date میلادی
```

- صحت تبدیل‌ها با کتابخانهٔ مرجع `jalaali-js` مقایسه شده است: **۷۳٬۴۱۴ تبدیل در هر جهت، صفر
  ناهمخوانی** (بازهٔ ۱۳۰۰ تا ۱۵۰۰ شمسی)، و `npm run test:unit` همین موضوع را در هر اجرا بررسی می‌کند.

## ۸) مقاوم‌سازی و عیب‌یابی

برنامه طوری ساخته شده که با نبودِ تنظیمات هم «بی‌صدا» از کار نیفتد:

| وضعیت | رفتار برنامه |
|--------|----------------|
| `.env` نیست | خودکار ساخته می‌شود (`postinstall` و `dev:open`)؛ اگر نشد، کادر راهنما در صفحهٔ ورود |
| `AUTH_SECRET` نیست (توسعه) | کلید موقت ثابت + هشدار فارسی در کنسول و کادر راهنما در صفحهٔ ورود |
| `AUTH_SECRET` نیست (تولید) | ورود غیرفعال + پیام فارسی «کلید امنیتی نشست تنظیم نشده است» با راه‌حل |
| پایگاه داده نیست | فرم‌ها غیرفعال و کادر راهنما با دستور `npm run db:setup` (بدون خطای ۵۰۰) |
| فایل‌های قلم نیست | استفاده از قلم پیش‌فرض سیستم (ساخت پروژه هرگز شکست نمی‌خورد) |
| خطای پیش‌بینی‌نشده | `app/error.tsx` و `app/global-error.tsx` پیام فارسی + راه‌حل + جزئیات فنی |

**چرا قلم‌ها با `@font-face` سرو می‌شوند؟** در `next/font/local` فایل قلم در زمان «ساخت»
به‌عنوان ماژول خوانده می‌شود و اگر نباشد، `npm run build` با خطای `Module not found` شکست
می‌خورد. با `@font-face` (فایل‌ها در `public/fonts`) نبود قلم فقط به‌معنی استفاده از قلم
پیش‌فرض سیستم است.

**چرا کلید موقت توسعه ثابت است؟** چون میدل‌ور در محیط Edge و ستون‌های سرور در Node.js اجرا
می‌شوند. اگر هر کدام کلید تازه‌ای می‌ساختند، کوکی نشست برای دیگری نامعتبر می‌شد و کاربر در
حلقهٔ بی‌پایان ریدایرکت بین `/` و `/login` می‌افتاد. کلید ثابت این خطر را از بین می‌برد.

### اگر مشکلی پیش آمد

```bash
npm run doctor
```

گزارش فارسی می‌دهد: نسخهٔ Node، بسته‌های نصب‌شده، فایل `.env`، کلید `AUTH_SECRET`، وضعیت
پایگاه داده، قلم‌ها و آزاد بودن پورت ۳۰۰۰ — همراه با راه‌حل هر مورد.

| نشانه | راه‌حل |
|--------|---------|
| `npm install` بدون خطا تمام نشد | `npm run doctor` و بعد `npm run db:setup` |
| صفحهٔ ورود، کادر «پایگاه داده آماده نیست» | `npm run db:setup` (نیازی به بستن سرور نیست) |
| کادر «کلید AUTH_SECRET تنظیم نشده» | `npm run init:env` |
| پورت ۳۰۰۰ اشغال است | Next خودش پورت بعدی را می‌گیرد؛ آدرس چاپ‌شده در ترمینال را باز کنید |
| خروج ناخواسته از حساب | `npm run init:env` تا کلید دائمی تنظیم شود |
| بعد از `npm run build` سرور توسعه عجیب شد | سرور توسعه را ببندید و `npm run dev:open` را دوباره اجرا کنید |

> **نکته:** پیش از اجرای `npm run build` سرور توسعه را ببندید؛ هر دو از پوشهٔ `‎.next‎`
> استفاده می‌کنند.
