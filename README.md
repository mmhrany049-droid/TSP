# TSP — سامانه مدیریت تست، مطالعه و آمادگی آزمون

**TSP** = Test + Study + Prep — سامانه‌ای برای دانش‌آموز رشتهٔ **ریاضی-فیزیک** که تست‌های کتاب‌های
کمک‌آموزشی را سازمان می‌دهد، تاریخچهٔ حل را نگه می‌دارد و درصد و آمادگی را از روی همان تاریخچه
محاسبه می‌کند.

> **نسخهٔ فعلی: ۰.۲ (مرحلهٔ ۲ از ۶)** — زیرساخت (مدل دادهٔ Prisma، قالب فارسی/راست‌به‌چپ،
> ابزارهای پایه) و **سامانهٔ احراز هویت** (ثبت‌نام، ورود، محافظت از مسیرها، خروج) آماده است.
> صفحه‌های ماژول‌ها در مراحل بعدی کامل می‌شوند (نقشهٔ راه در پایان همین فایل).

## ۲) راه‌اندازی سریع

نیازمندی: **Node.js 20.9 یا بالاتر** (پیشنهاد: 22) و npm.

```bash
npm install        # نصب وابستگی‌ها + تولید خودکار کلاینت Prisma
npm run db:setup   # ساخت پایگاه دادهٔ محلی و هم‌گام‌سازی با schema
npm run dev        # اجرای برنامه روی http://localhost:3000
```

بررسی سلامت اتصال پایگاه داده: `http://localhost:3000/api/health`

### فایل محیطی

فایل `.env.example` را به `.env` کپی کنید و کلید نشست را هم بسازید:

```env
DATABASE_URL="file:./prisma/dev.db"
AUTH_SECRET="یک-رشتهٔ-تصادفی-بلند"
```

ساخت `AUTH_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

`DATABASE_URL` پیش‌فرض دارد و اگر `.env` نباشد هم برنامه کار می‌کند، اما **`AUTH_SECRET` برای
امضای کوکی نشست لازم است**؛ بدون آن NextAuth در حالت تولید خطا می‌دهد.

## ۳) فرمان‌های مفید

| فرمان | کار |
|--------|------|
| `npm run dev` | اجرای برنامه در حالت توسعه |
| `npm run build` / `npm start` | ساخت و اجرای نسخهٔ نهایی |
| `npm run lint` | بررسی کد با ESLint |
| `npm run typecheck` | بررسی نوع‌ها با TypeScript |
| `npm run test:unit` | آزمون‌های واحد (تاریخ شمسی، اعتبارسنجی فرم‌ها، ابزارهای امنیتی) |
| `npm run db:setup` | ساخت/هم‌گام‌سازی پایگاه داده + تولید کلاینت |
| `npm run db:deploy` | اعمال مهاجرت‌های موجود (محیط واقعی) |
| `npm run db:reset` | پاک‌کردن پایگاه دادهٔ محلی و ساخت دوبارهٔ آن |
| `npm run db:push` | هم‌گام‌سازی مستقیم schema با پایگاه داده |
| `npm run db:studio` | مرور داده‌ها با Prisma Studio |

### ساخت مهاجرت تازه

پس از هر تغییر در `prisma/schema.prisma`:

```bash
npx prisma migrate dev --name توضیح_تغییر   # ساخت فایل مهاجرت (نیازمند اینترنت معمولی)
npm run db:deploy                           # اعمال مهاجرت‌ها روی پایگاه داده
```

> **نکتهٔ فنی:** پروژه روی «موتور طرح‌وارهٔ جاوااسکریپتی» Prisma (بدون باینری بومی) تنظیم شده تا
> روی ویندوز و هر سیستم‌عامل دیگری **بدون دانلود فایل‌های سنگین** اجرا شود. این موتور هنوز
> آزمایشی است و برای `migrate dev` نمی‌تواند پایگاه دادهٔ سایه بسازد؛ به همین دلیل:
> • در کار روزمره از `npm run db:setup` (که از `db push` استفاده می‌کند) یا `npm run db:deploy`
>   استفاده کنید؛
> • ساخت *فایل* مهاجرت تازه را روی سیستمی با اینترنت معمولی انجام دهید (موتور کلاسیک خودکار
>   دانلود می‌شود).

## ۵) مدل داده

مدل دادهٔ `prisma/schema.prisma` بر پایهٔ سند `TSP_v0.2_docs/03_Data_Model_v0.2.md` نوشته شده و
۱۷ مدل دارد:

| گروه | مدل‌ها |
|------|---------|
| کاربر | `User` |
| کتاب و ساختار | `Book`, `BookNode` |
| مبحث | `Topic`, `QuestionTopic` |
| تست و تاریخچه | `Question`, `QuestionAttempt`, `PreviousSolvedEntry` |
| تدریس | `TeachingRecord`, `TeachingGoal` |
| آزمون | `Exam`, `ExamTopic`, `ExamQuestion`, `ExamAttempt`, `ExamAnswer` |
| برنامهٔ آینده | `FutureExamPlan` |
| مرور | `ReviewItem` |

### قواعدی که در مدل داده رعایت شده است

1. **`displayNumber` یکتا نیست** — شمارهٔ نمایشی در هر فصل از ۱ شروع می‌شود؛ شناسهٔ واقعی همان
   `Question.id` است.
2. **`BookNode` جدا از `Topic`** — اولی محل تست در کتاب است و دومی مفهوم آموزشی.
3. **تاریخچه فقط افزودنی** — هر بار حل، یک `QuestionAttempt` تازه می‌سازد و رکورد قبلی هرگز
   بازنویسی نمی‌شود.
4. **`PreviousSolvedEntry` با `QuestionAttempt` یکی نیست** — برای تست‌هایی که پیش از استفاده از
   برنامه حل شده‌اند.
5. **سختی ناشر، `isHard` و `isImportant` سه فیلد جدا هستند.**
6. **آمار از رکوردهای خام محاسبه می‌شود** — هیچ فیلد خلاصه‌ای جای تاریخچه را نمی‌گیرد.
7. **`onDelete` مناسب هر رابطه** — حذف کتاب، ساختار و تست‌هایش را پاک می‌کند (`Cascade`)؛ حذف
   یک تست بانک، سؤال آزمون را نگه می‌دارد و فقط پیوندش را خالی می‌کند (`SetNull`).

> **چرا enum نداریم؟** SQLite در Prisma از `enum` پشتیبانی نمی‌کند؛ مقادیر مجاز به‌صورت `String`
> ذخیره می‌شوند و مرجع تایپ‌شدهٔ آن‌ها در `lib/constants.ts` است.

## ۶) احراز هویت

ورود و ثبت‌نام با **NextAuth.js 5 (Auth.js)** و فراهم‌کنندهٔ **Credentials** انجام می‌شود:

- **ثبت‌نام**: `POST /api/auth/register` ورودی را با Zod بررسی می‌کند، گذرواژه را با bcrypt
  (۱۰ دور) هش می‌کند و کاربر را می‌سازد. ایمیل تکراری کد ۴۰۹ می‌گیرد.
- **ورود**: فرم ورود با `signIn("credentials")` وارد می‌شود؛ در `lib/auth.ts` ابتدا ایمیل پیدا
  و سپس گذرواژه با هش مقایسه می‌شود. نشست به‌صورت **JWT** در کوکی `HttpOnly` نگه داشته می‌شود
  (۳۰ روز).
- **محافظت از مسیرها**: `middleware.ts` همهٔ مسیرها را می‌گیرد و مسیرهای خصوصی را به
  `/login?callbackUrl=...` می‌فرستد؛ کاربر واردشده هم از صفحه‌های ورود/ثبت‌نام به داشبورد
  برمی‌گردد. میدل‌ور در Edge اجرا می‌شود، پس فقط `lib/auth.config.ts` سبک را می‌خواند و
  Prisma/bcrypt در آن بار نمی‌شود.
- **خروج**: دکمهٔ خروج در نوار بالایی کوکی نشست را پاک می‌کند.

نکته‌های امنیتی رعایت‌شده: گذرواژهٔ هش‌شده هرگز از API بیرون نمی‌رود، پیام خطای ورود همیشه
عمومی است («ایمیل یا گذرواژه نادرست است») تا معلوم نشود کدام ایمیل ثبت شده است، و مقصد
بازگشت پس از ورود (`callbackUrl`) با `safeCallbackUrl` پاک‌سازی می‌شود تا دامنهٔ بیرونی
جای مسیر داخلی ننشیند.

## ۷) تاریخ شمسی

- همهٔ تاریخ‌ها به شکل **میلادی/ISO** ذخیره می‌شوند و فقط برای نمایش به شمسی تبدیل می‌شوند.
- توابع آماده در `lib/date.ts`:

```ts
formatJalali(new Date("2025-09-22"));                  // ۱۴۰۴/۰۶/۳۱
formatJalali(new Date("2025-09-22"), { long: true });  // ۳۱ شهریور ۱۴۰۴
parseJalali("1404/06/31 14:30");                       // Date میلادی
```

- صحت تبدیل‌ها با کتابخانهٔ مرجع `jalaali-js` مقایسه شده است: **۷۳٬۴۱۴ تبدیل در هر جهت، صفر
  ناهمخوانی** (بازهٔ ۱۳۰۰ تا ۱۵۰۰ شمسی)، و `npm run test:unit` همین موضوع را در هر اجرا بررسی می‌کند.
