# TSP — سامانه مدیریت تست و آمادگی آزمون

TSP is a smart platform for managing tests, organizing your studies, and preparing effectively for exams.
تی‌اس‌پی یک سامانه هوشمند برای مدیریت تست‌ها، برنامه‌ریزی مطالعه و آمادگی مؤثر برای آزمون‌هاست.

**نسخه ۰.۱** — پیاده‌سازی کامل هر یازده ماژول سند `docs/spec/02` روی یک برنامه وب فارسی/راست‌به‌چپ.

---

## ۱. اجرای سریع

نیازی به نصب هیچ کتابخانه‌ای نیست؛ برنامه فقط با **کتابخانه استاندارد پایتون ۳.۱۰+** اجرا می‌شود
(SQLite و `http.server` در خود پایتون موجودند).

```bash
python3 run.py                 # http://127.0.0.1:8787
python3 run.py --port 9000     # تغییر پورت
python3 run.py --host 0.0.0.0  # دسترسی از شبکه/پیش‌نمایش
python3 run.py --db /path/to/tsp.db --open
```

پایگاه داده در `data/tsp.db` ساخته می‌شود و **در اولین اجرا خالی است**. برای آشنایی سریع با
برنامه، در صفحه «داده و پشتیبان» دکمه **بارگذاری داده نمونه** را بزنید (نمونه بر پایه فصل ۱
شیمی ۲ مبتکران: ۱۳ گره ساختاری، ۶ مبحث، ۳۵ تست، سابقه قبلی، آزمون چکاپ و آزمون جامع).

## ۲. قابلیت‌ها بر پایه سند ۰۲

| ماژول | وضعیت | مسیر در برنامه |
| --- | --- | --- |
| مرکز منابع (درس/کتاب/ساختار کتاب) | ✅ | `#/books`, `#/books/{id}` |
| درخت مباحث آموزشی | ✅ | `#/topics` |
| بانک تست | ✅ | `#/questions` |
| ثبت تلاش جدید | ✅ | `#/entry`, پنجره ثبت سریع |
| ورود حل‌های قبلی (سابقه قبلی) | ✅ | `#/history`, `#/settings` |
| مرور هوشمند | ✅ | `#/review` |
| تدریس و عقب‌ماندگی | ✅ | `#/teaching` |
| مدیریت آزمون | ✅ | `#/exams`, `#/exams/{id}` |
| اجرای آزمون (چند اجرای مستقل) | ✅ | `#/exams/{id}/attempt/{attemptId}` |
| آمادگی آزمون | ✅ | `#/readiness` |
| تحلیل چندسطحی و داشبورد | ✅ | `#/analytics`, `#/dashboard` |
| داده، پشتیبان و یکپارچگی | ✅ | `#/settings` |

نکات پیاده‌سازی بر پایه سندهای دیگر:

- **جداسازی ساختار کتاب از مبحث آموزشی** (قاعده ۳): `book_node` و `topic` دو موجودیت جدا با
  درخت مستقل‌اند؛ یک تست هم مکان کتاب دارد و هم می‌تواند به چند مبحث وصل باشد.
- **آزمون چکاپ/جامع و تست‌های مخلوط** (قواعد ۴ و ۵): گره‌های ارزیابی و مجموعه‌های مخلوط فقط
  درخت کتاب را می‌سازند و به‌صورت خودکار مبحث نمی‌شوند؛ اتصال آموزشی فقط با انتخاب صریح کاربر.
- **سه مفهوم سختی** (قاعده ۶): `publisher_difficulty` (سختی ناشر)، `hard` و `important`
  (ارزیابی شخصی کاربر) سه فیلد جدا هستند و روی هم نوشته نمی‌شوند.
- **تاریخچه فقط افزودنی** (قاعده ۷): هر تلاش یک رکورد تازه می‌سازد؛ رکورد قبلی ویرایش نمی‌شود و
  تنها راه خروج از محاسبات، «باطل‌کردن» با ثبت دلیل است که رکورد را نگه می‌دارد.
- **سابقه قبلی ≠ تلاش جدید** (قاعده ۸): جدول `previous_question_entry` جدا از `question_attempt`
  است و تاریخ حل در آن اجباری نیست.
- **Exam ≠ ExamAttempt** (قاعده ۹): یک آزمون می‌تواند چند اجرای مستقل با کارنامه جداگانه داشته باشد.
- **آمار از داده خام** (قاعده ۱۰): همه شاخص‌ها در لحظه از `question_attempt` و سابقه‌ها محاسبه
  می‌شوند و هیچ مقدار خلاصه‌ای جای سوابق را نمی‌گیرد.

## ۳. تاریخ شمسی

- تاریخ‌ها با تقویم جلالی **نمایش** داده می‌شوند و در پایگاه داده به‌صورت UTC ایزو ذخیره می‌شوند.
- ورودی تاریخ هم شمسی و هم میلادی پذیرفته می‌شود: `1404/06/31`، `1404/6/31 14:30`،
  `1404-06-31`، `2025-09-22T14:30:00Z` و واژه «اکنون».
- تبدیل‌ها با الگوریتم مرجع پیاده‌سازی و در آزمون‌ها بررسی شده‌اند (۱۴۰۴/۰۱/۰۱ = ۲۰۲۵-۰۳-۲۱).

## ۴. آزمون‌ها

```bash
python3 -m unittest discover -s tests -p "test_*.py"   # ۵۹ آزمون سرتاسری API
python3 tests/test_api.py -v                            # اجرای مستقیم با نمایش جزئیات
node tests/ui_smoke.mjs http://127.0.0.1:8787           # آزمون دودی رابط کاربری (اختیاری، نیاز به jsdom)
```

- `tests/test_api.py` هر ماژول را روی یک **پایگاه داده موقت مستقل** و از راه HTTP واقعی آزمایش
  می‌کند (اعتبارسنجی، قواعد سابقه، تبدیل تاریخ، آماری).
- `tests/ui_smoke.mjs` با jsdom همه مسیرهای رابط کاربری را با داده واقعی سرور می‌گذراند و خطاهای
  جاوااسکریپت را گزارش می‌کند: `npm install jsdom` (هیچ وابستگی‌ای به مخزن اضافه نمی‌کند).

## ۶. گردش کار پیشنهادی

1. **مرکز منابع**: درس، کتاب و ساختار گره‌های کتاب (فصل/درس/تست‌های مخلوط/آزمون چکاپ/جامع) را بسازید.
2. **مباحث آموزشی**: درخت مباحث را جدا از کتاب بسازید و تست‌ها را به مباحث وصل کنید.
3. **بانک تست**: تست‌ها را یکی‌یکی یا با ورود گروهی CSV وارد کنید
   (ستون‌ها: `book,book_node_path,display_number,question_code,correct_answer,publisher_difficulty,topic_paths,reference,notes,important,hard,result,user_answer`؛
   قالب آماده را از «داده و پشتیبان» بگیرید).
4. **سابقه قبلی**: تست‌های حل‌شده پیش از راه‌اندازی برنامه را یک‌جا وارد کنید (تاریخ اختیاری است).
5. **ثبت تلاش**: هر بار حل تست را ثبت کنید؛ نتیجه به‌صورت خودکار از مقایسه پاسخ با کلید تعیین می‌شود.
6. **مرور هوشمند**: موارد باز با دلیل و اولویت ساخته می‌شوند؛ می‌توانید دسته‌ای مرور کنید
   (نسبت به تدریس، آزمون‌های پیش‌رو و هدف‌های عقب‌مانده).
7. **تدریس و آزمون**: وضعیت تدریس مباحث، هدف‌های تست، آزمون‌ها و اجرای مستقل آن‌ها را مدیریت کنید.
8. **آمادگی و آمار**: برآورد آمادگی (پوشش، تسلط، بدهی مرور، تدریس، پیشرفت هدف، آزمون‌های گذشته)
   و تحلیل چندسطحی از داده خام را ببینید.

## ۷. پشتیبان‌گیری و انتقال

- **پشتیبان کامل**: `POST /api/backup` یک فایل `.db` در `data/backups` می‌سازد.
- **صدور/ورود JSON**: همه ۲۲ جدول داده در یک بسته JSON؛ ورود در دو حالت «ادغام» و «جایگزینی»
  (با پشتیبان خودکار پیش از جایگزینی).
- **یکپارچگی داده**: صفحه «داده و پشتیبان» یازده بررسی قواعد سند ۰۳ را اجرا می‌کند
  (شماره نمایشی تکراری، تست بدون مکان، سابقه بدون کلید، رکورد ناسازگار و…).

## ۸. محدودیت‌های نسخه ۰.۱

- تک‌کاربره و محلی است؛ احراز هویت و چند کاربری ندارد (طبق سند ۰۱).
- به‌جای FastAPI روی `http.server` ساخته شده تا **بدون هیچ نصب** اجرا شود؛ API همان ساختار
  REST/JSON را دارد و در صورت نیاز می‌توان لایه سرویس را به فریم‌ورکی مانند FastAPI منتقل کرد.
- نمودارها با SVG سبک و بدون کتابخانه رسم می‌شوند.
- تفاوت روش درخواست نامعتبر با کد ۴۰۴ پاسخ داده می‌شود (نه ۴۰۵).
