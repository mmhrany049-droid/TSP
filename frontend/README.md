# TSP Frontend

رابط فارسی و راست‌به‌چپ نسخه اول TSP. فقط از طریق REST API با بک‌اند حرف می‌زند و مستقیم به پایگاه داده وصل نمی‌شود.

پورت: **3000**

## پیش‌نیاز

- Node.js 20 یا جدیدتر
- npm
- بک‌اند روشن روی پورت 8000 (راهنمای `backend/README.md`)

## اجرا

```bash
cd frontend
npm install
npm run dev
```

سپس در مرورگر باز کنید: http://localhost:3000

در ویندوز هم همین دستورها در PowerShell یا CMD کار می‌کند.

ساخت نسخه تولید:

```bash
npm run build
npm start
```

## اتصال به بک‌اند

به‌طور پیش‌فرض مرورگر به آدرس نسبی `/api/v1` درخواست می‌زند و سرور Next آن را به `http://127.0.0.1:8000` پروکسی می‌کند. برای این حالت لازم نیست متغیر محیطی تنظیم کنید، ولی بک‌اند باید روشن باشد.

اگر می‌خواهید مرورگر مستقیم به بک‌اند وصل شود، فایل `.env.local` بسازید:

```bash
NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1
```

در این حالت CORS بک‌اند باید مبدأ `http://localhost:3000` را بپذیرد. این مقدار در `.env.example` بک‌اند هست.

مقصد پروکسی را می‌توان با `API_PROXY_TARGET` عوض کرد. نمونه در `.env.example` است.

توکن JWT در `localStorage` با کلید `tsp.access_token` نگه داشته می‌شود و با هدر `Authorization: Bearer ...` فرستاده می‌شود. اگر توکن نباشد، صفحات داخلی به ورود برمی‌گردند.

## سناریوی تست در مرورگر

بک‌اند را اول روشن کنید، بعد فرانت‌اند را. این مسیر را دقیق طی کنید:

1. به http://localhost:3000 بروید. به صفحه ورود می‌روید.
2. روی «ثبت‌نام» بزنید. نام، ایمیل و رمز حداقل ۸ کاراکتری را وارد کنید.
3. بعد از ورود، داشبورد و «مسیر شروع» را می‌بینید.
4. «کتاب جدید» را بزنید. مثلاً عنوان `شیمی ۲ مبتکران`، درس `شیمی`، ناشر `مبتکران`، پایه `یازدهم`.
5. در صفحه کتاب، عنوان `فصل ۱` را بنویسید و «افزودن فصل» را بزنید.
6. فصل را انتخاب کنید، عنوان `الگوها و روندها` را بنویسید و «افزودن بخش زیر گره انتخاب‌شده» را بزنید.
7. بخش را انتخاب کنید. شماره نمایشی `12` و پاسخ صحیح `3` را وارد کنید و «ثبت تست» را بزنید.
8. «حل تست» را بزنید. پاسخ `3` را وارد کنید و «ثبت پاسخ» را بزنید.
9. باید مهر «درست»، پاسخ صحیح، و درصد این تست / این کتاب / کل تلاش‌ها را ببینید.
10. یک بار دیگر پاسخ `1` را ثبت کنید. نتیجه «غلط» می‌شود و درصد این تست به ۵۰٪ می‌رسد.
11. در جدول تاریخچه باید هر دو تلاش جدا باشند. تلاش اول هنوز «درست» است.
12. دکمه «بی‌پاسخ» یک رکورد سوم با نتیجه بی‌پاسخ می‌سازد و درصد را دوباره حساب می‌کند.
13. از منو «تاریخچه تلاش‌ها» را باز کنید. هر سه رکورد باید آن‌جا هم باشند.

برای دیدن قاعده شماره غیریکتا، در دو فصل مختلف تستی با شماره `12` بسازید. هر دو ذخیره می‌شوند و با شناسه داخلی کوتاه از هم جدا دیده می‌شوند.

## اگر خطا دیدید

- «اتصال به سرور برقرار نشد»: بک‌اند روی پورت 8000 روشن نیست، یا از پوشه `backend` اجرا نشده.
- صفحه سفید یا بازگشت به ورود: توکن منقضی شده. دوباره وارد شوید.
- خطای ۴۲۲: فیلد الزامی خالی است یا رمز کمتر از ۸ کاراکتر است.
- درصد خالی (`—`): هنوز تلاشی ثبت نشده.

## صفحات

| مسیر | کار |
|---|---|
| `/login` و `/register` | ورود و ثبت‌نام |
| `/` | داشبورد، درصد کل، مسیر شروع |
| `/books` و `/books/new` | فهرست و ساخت کتاب |
| `/books/[id]` | درخت فصل/بخش، افزودن تست، حل |
| `/questions/[id]` | حل تست، نتیجه، درصد، تاریخچه |
| `/attempts` | همه تلاش‌ها، بدون بازنویسی |

رابط کاملاً فارسی و `dir="rtl"` است. تاریخ‌ها شمسی نمایش داده می‌شوند. حالت بارگذاری، خطا و خالی بودن داده در صفحه‌ها مدیریت شده است.
